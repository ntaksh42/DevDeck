# 依頼の読み方

人が DevDeck の Agent パネルから、特定の結果 HTML に紐づかない依頼 (パイプラインの失敗の調査、要約、質問など) を残します。作業前に必ず確認すること。

- 場所: `{notes_root}\ask-{番号}\*.md`（1 件 1 ファイル）。**フォルダ直下の `.md` だけが未対応**。
  `_done/`（対応済み）・`_draft/`（人の下書き）・`_trash/`（削除済み）と `.` で始まるファイルは読まない。
- front-matter の `context` は依頼の対象 (例: `Pipeline run 412 (CI-main) https://...`)。無ければ対象なしの依頼。
- Azure DevOps には書き込まない。`az` CLI は使えない (DevDeck が未ログインの状態で起動する)。
  `git push` もしない (DevDeck が push 先を無効にして起動する)。fetch や手元での commit はしてよい。
  必要な情報は front-matter の `context_file` (DevDeck が取得した資料。読み取り専用) と手元のファイルから得る。
  足りなければ、何が要るかを質問として返信する。
- `kind` は依頼の種類: `investigate`（調べて原因・結論を返信する）、`summarize`（要約を返信する）、
  `question`（質問に答える）。無ければ `question`。
- 本文の後ろの `<!-- reply user {時刻} -->` 以降は人の返信。最後の返信が新しい指示。
  `user` 以外の名前 (`claude` / `codex` など) の返信はエージェントによるもの。

## 手順

1. 依頼に答える。答えはファイル末尾に `<!-- reply {自分の名前} {ISO 時刻} -->` の行と Markdown の本文を追記する
   (既存部分は書き換えない)。名前は英小文字 1 語 (例: `claude`, `codex`)。
2. 答え終えたファイルは front-matter に `resolved: 一行要約` を追記して `_done/` へ移す。本文は書き換えない。
3. 質問がある・対応できない場合は、理由を返信として追記し、ファイルは移さずに残す
   （最後の返信がエージェントのメモは、DevDeck で「人の対応待ち」と表示される）。
4. ファイルを書き換えるときは一時ファイルに書いてから置き換える（書きかけを読ませない）。
