# Inbox 仕様

`docs/spec-overview.md` の Views 表から分けた Inbox の現状仕様。Inbox を変更するときは、このファイルを同じ変更で更新する。

## 本体 (検出・状態・一覧・プレビュー・キー操作)

自分が対応すべきものを 1 か所で見て、その場で処理するビュー (サイドバー最上位に固定表示、ドラッグ並べ替え対象外、Open 件数のバッジ付き。`G` → `I`)。対象は自分に向けられたコメントだけで、レビュー対象 PR のコメントのうち**自分へのメンション** (`pr_mention`)、**所属するグループ/チームへのメンション** (`pr_group_mention`、表示は `Team`。所属グループは My Reviews と同じ 1 時間キャッシュ)、**自分が参加したスレッドへの返信** (`pr_reply`)、自分が作成した PR (キャッシュ済みの active PR、最新 60 件) への他者のコメント (自分が参加していないスレッドは最初のコメントだけを数え、他の人同士のやり取りでは件数を増やさない)、WI の**メンション** (`wi_mention`) と WI の**返信** (`wi_reply`、表示は `WI reply`。自分がコメントした後の他者のコメント、または DevDeck でフォロー中の WI への他者のコメント)。Returned・新規アサイン・承認待ち・エージェントの返信待ちは My Reviews / My Items / Pipelines / Agent パネルで扱い、Inbox には出さない (2026-10 に対象から外した。以前のバージョンが保存した `pr_review_request` / `pr_returned` / `wi_assigned` の Open 行は次の同期で Done にし、Done の一覧では 30 日の保持期間が過ぎるまで元の種別名で表示する)。検出は PR 同期 (最新 100 件のレビュー対象 PR) のスレッド取得に相乗りし、通知設定に関係なく動く (通知用の `pr_comment_seen` とは別の `action_inbox_cursor` を持つ。PR を初めて観測したときは、既存コメントのうち自分 / 所属グループへのメンションで、スレッドが未解決かつその後に自分が返信していないものだけを項目にし、それ以外は基準の記録だけ。途中からレビュアーに追加された PR でも待っている依頼を落とさないため。WI は初回観測では基準の記録だけ)。状態 (`open` / `snoozed` / `done`) は Azure DevOps に書き戻さずローカルの `action_inbox_items` だけで持つ。項目は会話ごとに 1 行 (PR はスレッド、WI は WI 単位)。同じ会話に自分宛ての新しいコメントが来ると、その行を最新のコメントで更新し (検出時刻も更新するので Open の一覧の先頭に来る)、待っているコメント数 `hitCount` を 1 増やす。Done だった行は Open に戻して 1 から数え直し、Snooze 中の行は起こす。待っている会話は強い方の種別を保つ (Mention > Team > Reply。メンションに通常の返信が続いても Mention のまま)。一覧上部の Priority / Other / All で重要度を絞り込める (初期表示は All)。一覧の上端の列ヘッダー (Kind / Author / Repo・Project) のフィルタ ボタンは My Reviews と同じ `ColumnFilterDropdown` で値を絞り込み (テキスト条件の後・重要度の前に適用。候補はテキスト条件を通った行の値。閉じるとボタンへフォーカスが戻る)、`Clear column filters` で全解除する。組織・テキスト・重要度と同様に表示だけを絞る。Priority は明示的な PR / WI メンション (`pr_mention` / `wi_mention`)、Other はチーム宛てメンションと通常の返信 (`pr_group_mention` / `pr_reply` / `wi_reply`。Done に残る旧種別も Other)。分類基準は切替の直下に常時表示し、AI の判定やユーザーによる分類変更は使わない。会話の種別で分類するので、メンション後に通常の返信が来ても Priority に残る。重要度は Open / Done / Snoozed・組織・テキスト条件と組み合わせ、表示だけを絞る (非表示の項目の状態を変更せず、チェックも外すので一括 Done / Snooze に含めない)。サイドバーと Done / Snoozed の件数は重要度で絞らない状態全体の件数、一覧下端は表示中の件数。Tab / Shift+Tab で重要度切替に入り、矢印キー (Home / End も可) で切替、Enter / Escape で一覧に戻る (空の一覧でも可)。判断メモは前のコメントについて書いたものなので消し、次の同期で書き直す。同じコメントの再スキャンでは重複も再オープンもしない。一覧の行は `hitCount` が 2 以上のとき、時刻の手前に吹き出しアイコン付きで件数を出す。v27 で、それまでのコメントごとの行を会話ごとに 1 行にまとめた (最新コメントの行を残し、どれかが Open なら Open、次に Snoozed、すべて Done なら Done)。スレッドが Resolved / 削除された、コメントが削除された、自分がその後に返信した場合は同期時に自動で Done にする。PR が Completed / Abandoned になった場合 (PR 同期の成功後、Active PR とレビュー対象 PR のどちらのキャッシュにも無い。取得に失敗したプロジェクトや取得件数の上限に達したプロジェクトはキャッシュを残すので、そこの項目は閉じない) と、WI が Closed / Done / Completed / Removed になった場合 (WI 同期ごとに、Open のメンション項目の WI の状態をまとめて取得。My Work Items と同じ状態名で判定) も自動で Done にする。Snooze の期限が過ぎた項目は背景ジョブなしで Open に戻る。PR のスレッド項目は検出時にスレッドのコード位置 (ファイルと行。新しい側、削除行へのコメントは古い側) を `file_path` / `line` に保存し、一覧の行の先頭に `dashboard.ts:7` のように出す (v25 より前に保存された項目は、Open の間に次の PR 同期で埋める)。プレビューは上から、見出し (種別・リポジトリ・ブランチ・作成者・検出時刻)、1 行の要約 (PR 項目は作成者 / Draft / 自分の投票 / 未投票の必須レビュアー数 / Auto-complete、WI 項目は Reason・最終更新・親 WI (クリックで DevDeck 内で開く))、Claude の判断メモ (後述。設定でオンのときだけ)、操作ボタン (Resolve + Done / Done / Snooze、Done の一覧では Reopen、Snoozed の一覧では Unsnooze)、畳んだ説明 (PR の説明は Markdown を整形して表示、WI の Description はサニタイズ済み。`D` か `▸ Description` で展開)、会話 (`THREAD` / `DISCUSSION` の小見出しの下にスレッド / WI のコメント。小見出しは他のプレビューの青い帯より控えめな下線付きの文字)、行コメントならコメント対象の前後 5 行のコードと PR 内で未解決の会話数 (同じファイルの件数を含む。既存の `list_pull_request_changes` と `get_pull_request_file_diff` を再利用し、コメント行を強調。取得できない理由や失敗は枠内に 1 行で出し、返信・Done は妨げない)、返信欄の順に並べ、関連リンク (後述) は畳んだ説明の直下、会話の手前に置く。返信欄は下端に固定されるので、リンクを下に置くと長いスレッドでは返信欄の裏に隠れてしまうため。判断に一番必要なコメントを先頭近くに置き、PR の説明は既定で畳む。Done / Snooze / Reopen (返信・コメント・Resolve 後の自動 Done を含む) した項目は再取得を待たずに一覧から消し、同じ位置の次の行 (末尾なら 1 つ前) を選んで一覧にフォーカスを残す。保存に失敗した場合は行を戻してトーストで知らせる。Done は 30 日で削除する。画面は `DockableWorkspace` (レイアウトは `azdodeck:layout:inbox:dockview:v1` に保存) で、Items (一覧。以前の Inbox / Snoozed / Done タブは廃止し、他の一覧と同じ共通ステータスバー (下記「一覧ペインのステータスバー」) の `Done N` / `Snoozed N` ボタンで一覧をその状態に切り替える。押すと一覧が Done / Snoozed に切り替わり、タブ帯に解除チップ (`Done ✕` / `Snoozed ✕`) が出る。チップの ✕、もう一度同じボタン、一覧上の `Esc` で Open の一覧へ戻り、フォーカスは一覧へ戻る。ステータスバーの左は `N items`、右端の `?` が Help の Inbox の節を開く。以前の 3 行のキー操作ヒントは `?` に置き換えた。タブ帯右端に解除チップ、組織が 2 件以上のときの組織セレクト、畳んだ `Ctrl+F` フィルタを置く)、その右に Conversation (プレビュー。既存の `PrThreadCard` でスレッドを表示し、返信 / Resolve・Reactivate をその場で行う。タブ帯右端に「Open in DevDeck (Shift+Enter)」「Open in Azure DevOps (O)」のアイコンボタン + 共通のズーム + `⋯` View options (Copy URL / Ask the agent))、の 2 パネル。エージェントとの会話は全 View 共通の Agent パネル (後述) で行う。項目を選ぶと Conversation を前面に出す。返信欄 (PR スレッドの返信欄と WI のコメント欄) はプレビューの下端に固定し、長いスレッドでもスクロールせずに書ける。PR の返信欄はスレッドの開閉に関係なく常時表示し、項目を切り替えると下書きをクリアする。PR の返信欄では `Ctrl+Enter` で返信 + Done、`Ctrl+Shift+Enter` で返信 + Resolve + Done (未解決スレッドのみ。ヒント行に表示する。返信の後で Resolve に失敗した場合は返信は投稿済みなので下書きを消し、項目は Open のまま理由をプレビューに出す)。WI のコメントには 1 件ごとに Reply を付け、押すとそのコメントの 1 行引用と投稿者への @メンション (`createdById` があれば通知される `@<id>` に変換) を入れた返信欄にフォーカスする (WI コメントには返信スレッドが無いため新規コメントとして投稿する)。メンション元のコメントは古くても常に表示する。返信の送信、WI へのコメント、スレッドの Resolve は成功後に項目を Done にする (Reactivate は状態を変えない)。プレビューのスレッドは My Reviews と同じ `prReview` クエリキャッシュを共有する。

## 関連リンク

**関連リンク** (`Related links` 領域): 返信するときに辿りたい先を、項目を選んだだけで漏れなく並べる (件数の上限なし)。重複は除き、出どころごとに `Linked` / `Description` / `Comments` / `Attachments` の見出しで分けて、この順に番号を振る。PR 項目は `Linked` に PR の Development 欄の WI (`list_pull_request_work_items`、My Reviews の Linked Work Items と同じ `prWorkItems` キャッシュ) と説明文の `AB#n` を、タイトルと状態付きで出す (タイトルの取得は先頭 8 件まで。それ以降は番号だけ)。`Description` は PR の説明、`Comments` は対象スレッドの人が書いたコメントから拾う。WI 項目は `Linked` に関連 WI (親 / 子 / 関連などの種別と状態付き) と関連 PR (状態と自分の投票付き)、`Description` に本文、`Comments` にメンション元を先頭にした全コメント (レンダリング済み HTML のリンク先を含む)、`Attachments` に添付ファイルを出す。項目自身の PR / WI / URL は含めない。リンクは `AB#n` / `#n` (WI)、`!n` (PR)、http(s) URL で、WI は DevDeck 内の Work Item Search、PR は My Reviews (リポジトリが分かれば指定して) へ、URL は外部ブラウザで開く。クリックのほか、一覧から `1`-`9` で先頭 9 件を開き、10 件目以降は Tab と Enter で開く。Read-only 検証モードでは返信と Resolve を無効にする。一覧は他のグリッドと同じ選択行の色とフォーカス枠を使い、選択行だけを Tab 順に入れる。クリック / 行移動で行自体にフォーカスし、`Ctrl+G` はプレビューや Agent の会話一覧から選択行へ戻る。同期・返信 / Resolve・フィルタ等で行が入れ替わっても一覧が持っていたフォーカスを復帰し、プレビュー入力中のフォーカスは奪わない。キーボード (My Reviews の割当に揃える): `↑↓`/`J K`/`Home`/`End`/`PageUp`/`PageDown` で行移動、`Enter`/`→` でプレビューへ (`Esc` で一覧へ戻る)、`Shift+Enter` で DevDeck 内の対象 PR (My Reviews) を開く、`O` / `Ctrl+Enter` でブラウザ (`Ctrl+Enter` はプレビュー・ツールバーからも有効、返信入力中は送信)、`E` で Done (Done の一覧では Reopen)、`Shift+E` で Resolve + Done (未解決スレッドの項目のみ。プレビューのボタンと同じ)、`Z` で Snooze (Snoozed の一覧では解除。開いたメニューでは `1`-`5` でプリセットを選べる。カスタム日時の入力中は数字を奪わない。この数字キーは共通の `SnoozeMenu` なので My Reviews / Work Items でも同じ)、`X` で選択行に印を付け外し、`Shift+↓` / `Shift+↑` で印の範囲を広げる (印は行に ✓ とステータスバーの `N marked (Esc clears)` で示し、印のある間の `E` / `Z` は印の付いた全項目に 1 リクエストで適用し、`Esc` で印を消す。印は一覧から消えた項目の分が自動で外れる。Shift+E の Resolve + Done は選択行だけ)、`U` で直前の Done / Snooze / Reopen / Resolve + Done を元に戻す (10 秒間・直近 1 回の操作。一括操作は全項目をまとめて戻す。状態変更の保存完了前に取り消した場合は、その保存完了を待ってから元の状態を書き戻す。ローカルの Inbox 状態だけを戻し、Azure DevOps で Resolve したスレッドはそのまま。一覧を切り替えると取り消せなくなる。ステータスバー左に「Marked done」等と Undo ボタンを出す)、`Space` / `Shift+Space` で一覧にフォーカスしたままプレビューを約 1 画面スクロール、`D` でプレビューの畳んだ説明 (PR の説明 / WI の Description) を展開・折りたたみ (項目を切り替えると畳む)、`Esc` で Done / Snoozed の一覧から Open へ戻る、`M` / `Ctrl+M` (設定の Focus comment、My Reviews / Work Items と同じ) で返信欄を開く (WI メンションはメンション元コメントへの Reply、無ければコメント欄)、`Shift+R` で Claude の返信案を返信欄に入れる、`Q` で Agent パネルをその項目の PR / WI を対象に開く (PR のメンション / 返信は対象スレッドも渡す)、`C` で URL コピー、`/` でフィルタ。項目を選ぶだけで (`Q` を押さなくても) Agent パネルの対象がその項目の PR / WI (メンション / 返信は対象スレッド付き) になる。表示中の一覧 (Done / Snoozed の切替・組織・テキストフィルタ適用後) は Agent パネルの `+ This list (N)` で足せる。コマンド: `list_action_inbox_items` (`state` = `open` / `snoozed` / `done`、`organizationId`、`limit`) / `get_action_inbox_counts` / `set_action_inbox_item_state` (`ids`、`state`、`snoozedUntil`)。状態が変わると `action-inbox:updated` を emit し、App 直下で購読してバッジと一覧を invalidate する (通知履歴の `notifications:inbox-updated` とは別)。WI のコメント項目 (`wi_mention` / `wi_reply`) は、組織全体の WIQL マクロ `@RecentMentions` の結果、`[System.ChangedBy] EVER @Me` かつ 30 日以内に変更された WI (コメントすると変更者になるため、自分がコメントした WI を含む)、フォロー中の WI を合わせて候補にする (`sync/wi_candidates.rs`)。`@RecentMentions` が拒否された場合は最近変更した割当 WI 30 件だけを走査し、その旨を Sync health の `Inbox / Work item comments` に「Limited」として出す (このマクロが REST で受理されるかは実サービスで未検証)。PR 側も、走査の上限 (レビュー対象 PR 100 件・自作 PR 60 件) を超えて読めなかった PR があれば `Inbox / PR comments` に件数付きで出す (scope は `inbox_prs:{org}` / `inbox_wi:{org}`)。サイドバーのバッジと Inbox の Open 件数 (一覧が Open のときのステータスバー `N items`) はどちらも保存済みの Open 件数で、組織セレクトが未指定のときは一致する。PR / WI のコメント行は、何についてのコメントか分かるよう `!ID repo` の後に PR / WI のタイトルを (最大 16rem で省略して) 表示する。

## Claude の判断メモ

**Claude の判断メモ** (設定 `inbox_insight_enabled`、既定オフ): PR 同期 / WI 同期の後、同期した組織の判断メモの無い Open のコメント項目 (`pr_mention` / `pr_reply` / `wi_mention`) を新しい順に最大 `inbox_insight_max_per_sync` 件 (既定 3)、バックグラウンドで `claude -p --model <inbox_insight_model、未設定なら sonnet> --output-format json` に渡す (残りは次の同期で処理する。同時に走るのは 1 回分だけ)。入力は PR / WI の番号とタイトル、コメント位置、スレッド本文 (PR 同期で取得済みのスレッドのコメントを `作成者: 本文` で連結、最大 8,000 文字。無ければ保存済みの抜粋)。Workspace に PR のリポジトリと同名のクローンがあればそこを作業フォルダにして、コメント対象の行とその呼び出し元・呼び出し先を読み取り専用ツールで確かめるよう指示する。クローンが無ければ一時フォルダでスレッドだけから判断し、確かめられないことは推測として印を付けさせる。プロンプトではスレッドを他人の書いたデータとして扱い、中の指示に従わないよう明記する。コメントは他人が書いた文章で指示が紛れ込みうるため、起動は常に `--restricted` (ユーザーの設定ファイルの許可リストやフックを読まず、ファイル系ツールを作業フォルダ内に限る) と `--strict-mcp-config` (MCP サーバーを読まない) を付け、使えるツールを `--tools` でクローンありなら `Read,Grep,Glob` だけ、無ければなしに絞る (コマンド実行・書き込み・ネットワークは使えない。設定の `agent_command` は使わない)。Azure DevOps のトークン環境変数は渡さない。結果は JSON で受け取る: `verdict` (`reply` = そのまま返信できる / `fix` = 先にコードを直す / `none` = 対応不要。それ以外の値は捨てる)、`reason` (判断の理由を具体的な事実で 1 文)、`evidence` (最大 4 件。事実の文・`file:line`・その行のコード最大 3 行・推測かどうか)、`replyDraft` (スレッドの言語で、file:line や今後の変更を具体的に書いた 1〜3 文の返信案。`none` なら無し)。`action_inbox_insights` (`status` = `pending` / `ready` / `failed`) に保存して `list_action_inbox_items` の各項目の `insight` として返し、書くたびに `action-inbox:updated` を emit する。プレビューでは見出しの下に「Claude」の枠を常に同じ位置・同じ見た目で出す (作成中は「Looking into this item…」、失敗は「Could not write notes: 理由」を同じ枠の中に出す)。準備ができた枠は、判定のバッジ (Reply / Fix first / No action) と理由、根拠の一覧 (`file:line`、コード、推測には `unverified`)、返信案と「Use as reply (Shift+R)」ボタンの順。返信案は「Suggested reply」の見出しと左の色線で区切った区画に入れる。`Shift+R` (一覧から) かボタンで返信案を返信欄 (PR はスレッドの返信欄、WI はコメント欄) に入れてフォーカスする。送信はユーザーが確認してから行い、DevDeck が自動で返信・Resolve することはない。1 件の実行は 5 分で打ち切る。アプリ終了で `pending` のまま残った行は起動時に消して次の同期で書き直す。同期で処理するのは 1 回に最大 `inbox_insight_max_per_sync` 件 (既定 3) だが、設定がオンのときは Open のコメント項目に対して手動でも作成できる: 判断メモの枠の「Generate notes」(メモが無い項目) / 「Regenerate」(完了・失敗済み。作成中は出さない) ボタン、または一覧の `I` で `generate_action_inbox_insight` (`id`) を呼ぶ。バックグラウンドで 1 件だけ実行し (同期の実行中は「another summary is being written」で拒否)、完了は `action-inbox:updated` で反映する。PR 同期のスレッド全文は残していないため、手動の作成は保存済みの抜粋から判断する。設定 `agent_workspace_path` (クローンを置く 1 つのフォルダ) があれば、PR のリポジトリ名と同名のサブフォルダ → Workspace → 結果フォルダの順で作業フォルダを選び、プレースホルダ `{workspace}` / `{repo}` / `{guide}` を使える。同じフォルダでも複数のエージェントを同時に起動できる。

## 検出が上限に達したとき

PR の走査上限 (レビュー対象 100 件・自作 60 件) を超えた、または WI のメンション検索 (`@RecentMentions`) が拒否されて縮退したとき、同期は Sync health の `Inbox / PR comments` / `Inbox / Work item comments` に警告 (`lastWarning`) を残す。Inbox の一覧下端のステータスバーは、その警告があると左のサマリに `Scan limited — some comments may be missing` を出し (ホバーで警告文)、設定を開かなくても取りこぼしの可能性に気づけるようにする (`useInboxScanLimit`: `["syncStates"]` クエリの `inbox_` で始まる scope の警告)。警告が無ければ何も出さない。

## 返信待ちのリマインダー (`W`)

自分がコメントした会話に対して「期限までに返信が無ければ知らせる」を、ローカルだけで設定する (Azure DevOps へは何も投稿しない)。

- **設定**: 一覧で項目を選んで `W` (プレビューの `⋯` の「Remind if no reply…」も同じ)。既存のスヌーズと同じ共通 `SnoozeMenu` が「Remind if no reply by」の見出しで開き (`1`-`9` でプリセット、カスタム日時、`Esc` で閉じる)、補足に判定範囲 (`Cleared when someone comments on this conversation (seen at the next sync). Nothing is posted.`) を出す。確定するとトーストで期限を知らせる。閉じると一覧の行へフォーカスが戻る。その会話に既に待機中のリマインダーがあるとメニューに「Cancel the reminder」が加わり、解除できる。同じ会話に設定し直すと期限と起点を更新する。Open / Snoozed / Done のどの一覧からでも設定できる (返信して Done にした後でも付けられる)。
- **会話の単位**: PR はスレッド (`repositoryId` + `subjectId` + `threadId`)、WI は WI 単位 (リポジトリ空・スレッド 0)。`reply_reminders` (スキーマ v31) に `waiting` / `cleared` / `fired` の状態で保存する。
- **返信の判定**: 追加の API 取得はしない。同期が会話あての新しいコメントを Inbox の行 (`pr_mention` / `pr_group_mention` / `pr_reply` / `wi_mention` / `wi_reply`) として保存するので、リマインダーを設定した時刻より後に検出された同じ会話の行があれば、他者が返信したとみなして `cleared` にする。判定範囲は Inbox の検出範囲と同じ (自分宛て・自分が参加した会話に限る。走査上限もそのまま)。判定は PR 同期と WI 同期のそれぞれの Inbox 更新の直後に走る。
- **期限切れ**: 期限が過ぎても返信が無ければ、会話を Inbox の行 (種別 `pr_waiting` / `wi_waiting`、表示は `Waiting`、重要度は Priority) として Open の先頭に出し、リマインダーを `fired` にする。同じ期限は二度出さない (再起動後も同じ)。起動していない間に過ぎた期限は次の同期で出す。Waiting 行は PR のクローズ・スレッドの Resolve では自動で Done にならず、Done / Snooze で処理する。Waiting 行の後に同じ会話のコメント行が検出されたら、その Waiting 行は自動で Done にする。
- **通知**: 期限切れを出した同期は `action-inbox:updated` に加えて `inbox:reply-reminders-due` (`organizationId` / `organizationName` / `items`) を emit する。フロントは既存のデスクトップ通知と同じ設定 (`desktop_notifications_enabled`、静音時間、本文プレビュー設定) に従ってトーストを出し、クリックで Inbox を開く (`showReplyReminderNotificationEvent`)。
- **コマンド**: `set_reply_reminder` (`organizationId`、`kind` = `pr` / `wi`、`subjectId`、`projectId`、`projectName`、`repositoryId`、`repositoryName`、`threadId`、`title`、`webUrl`、`dueAt`。期限は未来のみ) / `list_reply_reminders` (待機中のもの) / `clear_reply_reminder` (`id`)。ブラウザデモは同じ 3 つをメモリ上で持ち、期限切れの Waiting 行は作らない。
